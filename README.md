# Практична робота: Калькулятор суми з історією операцій

## Відповіді на контрольні запитання:

1. **Який метод використовується для отримання елемента сторінки за значенням його id, і що саме він повертає? Чому для такого вибору достатньо саме цього методу, а не потрібен пошук за CSS-селектором?**  
   Для пошуку використовується `document.getElementById()`, який повертає конкретний об'єкт DOM-елемента або `null`, якщо елемента з таким id не існує. Оскільки ідентифікатор id завжди унікальний у межах сторінки, цей метод є найпростішим і найшвидшим, тому немає потреби витрачати ресурси на універсальний пошук за селекторами.

2. **Чому значення властивості value текстового поля потрібно явно перетворювати функцією Number() перед арифметичною операцією?**  
   Властивість `value` за замовчуванням повертає текстовий рядок. Якщо не викликати `Number()`, знак `+` виконає конкатенацію (зчеплення рядків замість додавання чисел).

3. **Що станеться зі значенням "2" + "3", якщо не виконати перетворення типів, і чому?**  
   Отримаємо рядок `"23"`, оскільки між двома рядками оператор `+` виконує конкатенацію тексту.

4. **Яким чином атрибут onclick пов'язує кнопку в HTML-розмітці з функцією, оголошеною у файлі script.js?**  
   В атрибуті `onclick` зазначається ім'я функції із круглими дужками (наприклад, `onclick="calculate()"`). При натисканні на кнопку браузер реєструє клік та викликає відповідну функцію з файлу `script.js`.

5. **Чим підхід через атрибут onclick відрізняється від підписки на подію методом addEventListener()?**  
   `onclick` записується безпосередньо в HTML-коді й може містити лише один обробник. Метод `addEventListener()` викликається суто з JavaScript, дозволяє додавати кілька різних функцій на одну подію та забезпечує чітке розділення розмітки та коду.

6. **Чим відрізняється зміна вмісту наявного елемента через textContent від додавання нового елемента через createElement() і appendChild()?**  
   Властивість `textContent` оновлює (замінює) текст усередині вже наявного елемента, тоді як зв'язка `createElement()` + `appendChild()` створює новий тег у DOM-дереві й додає його в кінець контейнера, зберігаючи всі попередні записи.

7. **Чому для показу результату обчислення достатньо змінити вміст одного елемента, а для історії потрібно щоразу створювати новий?**  
   Для результату достатньо одного елемента, оскільки нам потрібна лише поточна відповідь (попередні значення стираються). Історія ж має накопичувати всі операції, тому під кожну нову дію генерується окремий вузол `<li>`.

8. **Що станеться зі списком історії, якщо замість appendChild() щоразу змінювати textContent контейнера історії?**  
   Кожен новий підрахунок буде повністю стирати весь попередній список, і в історії завжди залишатиметься лише один останній запис.

---

## Висновок:
У ході виконання роботи було практично опановано методи роботи з DOM у JavaScript. Реалізовано інтерактивний калькулятор суми: зчитування значень з інпутів через `value`, їх приведення до числового типу за допомогою `Number()`, відображення результату через `textContent` та динамічне додавання записів до блоку історії за допомогою методів `document.createElement()` та `appendChild()`. Оформлено стилі для контейнера історії операцій.
